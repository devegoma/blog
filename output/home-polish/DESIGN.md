# 巨大ロゴを軸にしたホーム画面の改善

## 最新の指定（以前の最終案より優先）

利用者の追加指定により、以下を反映する。

- PC はプロフィール下の左サイドバーにナビゲーションとタグを配置。モバイルは最上部のナビを右揃えにし、タグは記事一覧上の位置を維持する。
- チャコールの背景とカード、明るいシアンのアクセントを使う方向へ戻す。配色の参照は最初の Fuwari 添付画像。
- RSS・GitHub・X の3リンクは必須。ショートプロフィール内へまとめ、文字ラベルなしのアイコンのみで表示する。上部ナビとフッターからは移す。デザイン上の引き算で省略しない。実装ではアイコンにアクセシブル名を与える。
- PC の画面左側にショートプロフィールを配置。アバター、名前、短い紹介文に絞り、カテゴリ一覧などは追加しない。
- モバイルのショートプロフィールは記事一覧の下へ配置する。ヘッダー直下には置かない。
- 巨大ロゴはサイズを維持し、上下へ少し余白を追加する。
- 巨大ロゴ、背景イラストなし、導入コピーなしの方針は維持する。

要件定義と未確定事項にも、画面幅別のナビ・タグ・プロフィール位置と必須3リンクを反映した。リンク先 URL と正式な自己紹介文は実装時に確認する。プロフィール画像は元の添付画像を参考にした表示例。

今回の更新画像は `home-desktop-sidebar-navigation.png` と `home-mobile-right-navigation.png`。PC のプロフィールにあった文字の紹介リンクはプロフィール下のナビへ統合する。

モバイル画像も確認。最上部の「記事・タグ・紹介」は右揃え、タグは記事一覧上、プロフィールは記事一覧下に維持。プロフィールの RSS・GitHub・X は3アイコンのみで、文字ラベルと区切り線を削除した。2画面とも今回の配置・表示指定を画像上で確認した。リンクの動作や実機の操作領域は、本体実装時の検証対象。

## 出発点

`../home-refinement/home-desktop-large-logo.png` を基準にする。巨大な白いセリフ体ロゴ、黄色いアポストロフィ、ダーク背景、記事一覧の方向性を維持する。黄色と青で画面全体を塗り替えた案は今回の土台にしない。

今回の成果物は画面デザイン画像。記事、日付、読了時間はすべて表示確認用のサンプル。

## 判断基準

- 巨大ロゴの個性を残し、ブランド表示の重複を減らす。
- 最初の記事へ到達する距離を短くする。
- タイトル、要約、日付・タグ・読了時間に明確な強弱をつける。
- タグは記事を発見するリンクとして扱い、固定カテゴリを新設しない。
- 記事画像は文字を圧迫しない大きさに揃える。
- スマートフォンは PC の縮小にせず、文字の幅を優先する。
- 新規の検索、会員登録、購読フォーム、利用者数などを足さない。

## 検証の範囲

生成画像を目視で比較し、構図・視線の流れ・文字と余白の強弱を確認する。画像生成は正確な書体・文字列・寸法を保証しない。色の数値、キーボード操作、タップ領域、実機での読みやすさと表示速度は本体実装時に確認する。

大規模利用に耐える実装や、利用者獲得の成果を画像から実証したとは扱わない。

## 実装に引き継ぐ要点

- ロゴは既存の専用画像を使用し、サイト名を代替テキストとして付ける。文字を画面外へはみ出させない。
- 本文は DM Sans + Noto Sans JP、日付は IBM Plex Mono。日本語の記事見出しを欧文ロゴと同じサイズにしない。
- PC の記事見出しは 26–28px、本文は 16px、メタ情報は 12–13px を出発点にする。
- タイトルとサムネイルは同じ記事へのリンク。タグはタグページへのリンクとし、リンクを入れ子にしない。
- タイトルリンクのホバー・キーボードフォーカス時は下線等で操作対象を明示する。画像上の静的表示だけで動作確認済みとは扱わない。
- タグは複数付けられる。複数タグや長いタイトルでも折り返せる構造を使う。
- サムネイルがない記事も、タイトルと本文の開始位置を保つ。
- モバイルでは記事一覧の画像を非表示にし、文章の全幅を確保する。

## 反復 3 — PC の仕上げ

- メタ情報のタグ名を # なしへ統一。

- PC の最終案として選定。巨大ロゴは、画面の個性として意図的に維持した。装飾を増やして変化を作る方向には進めない。

## モバイルの設計

- ロゴは画面幅いっぱいの1行表示。PC の高さをそのまま持ち込まない。
- ナビゲーションは記事・タグ・プロフィールの3項目。外部リンクはフッター。
- タグの重複する見出しと一覧リンクを減らし、上部に記事が見えるようにする。
- サムネイル・矢印・時計は置かず、見出しと要約を全幅で読ませる。
- 記事見出しの大きさを揃え、長いタイトルだけを小さく縮めない。自然な意味のまとまりで折り返す。

## モバイルの確認と最終判断

出力: `home-mobile-final.png`。

巨大ロゴを1行で維持し、ナビとタグのあとに最初の記事が見える構成を確認。記事画像がなくても、日付・タグ・タイトル・要約・読了時間の順で読み進められる。1件目と3件目の長い見出しは2行、短い2件目は1行となり、文字の幅を優先できた。RSS と GitHub はフッターにまとまっている。

PC 3稿とモバイル1稿の計4枚を生成・確認し、記事を選ぶために必要な情報と装飾の役割が揃った段階で終了。この PC 最終稿とモバイル最終稿を、今回の画像上の完成案に選定する。

ロゴの存在感を残すことと、初回表示の記事量を最大化することにはトレードオフがある。今回は、依頼された巨大タイポグラフィーをブランドの核として残し、重複するナビや装飾を減らす方を選んだ。

実装時には画像で省略された複数タグ・長い文字列・画像なし・記事0件の状態を用意する。表示サイズは生成画像から逆算せず CSS で定義し、本文16pxと44px以上の操作領域を出発点に検証する。本体実装・操作テスト・ユーザーテストは今回の成果物に含まない。
