# 実装に引き継ぐ仕様

本体未構築のため、ここでは画面の設計のみを定義する。既存の requirements.md は変更しない。

## 構造

`header > nav` → `main > introduction > latest posts` → `footer`。

- サイト名からトップへ戻れる。
- ナビゲーションは「記事」「タグ」「このブログについて」。現在位置を文字と下線で伝える。
- 記事一覧は公開日の降順。先頭を固定のおすすめ枠に置き換えない。
- 「タグから探す」のチップはタグ別ページへのリンク。複数タグを持つ記事を固定カテゴリに分けない。
- 記事のタイトルは記事ページへの通常リンク。行全体をリンクにする際、内部にタグリンクを入れ子にしない。
- 記事画像のない場合も同じ文字の幅と位置を保つ。
- RSS と外部プロフィールへのリンクをフッターに置く。

## 視覚トークン（実装時の出発点）

| 用途           | 値                                            |
| -------------- | --------------------------------------------- |
| 背景           | `#0B1118`                                     |
| 見出し         | `#EDF1F5`                                     |
| 本文           | `#ADB9C7`                                     |
| 補助文字       | `#96A6B8`                                     |
| アクセント     | `#51C9F5`                                     |
| コンテンツ幅   | 最大 1120px                                   |
| PC の本文      | 16–17px、行高 1.8                             |
| モバイルの本文 | 16px、行高 1.8                                |
| ヒーロー見出し | 日本語明朝、PC 48–56px / モバイル 34–38px     |
| 記事見出し     | 日本語ゴシック、PC 24–26px / モバイル 20–22px |
| 余白の単位     | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px         |

ヒーロー以外はゴシック体に統一。本文の背景へ画像を重ねない。イラストのフェード範囲に本文が入る場合は不透明な背景を確保する。

## モバイル

- 390px 幅を基準に、320px でも横スクロールを発生させない。
- 左右余白 20–24px。記事タイトル・本文の幅を画像より優先する。
- モバイルの記事一覧ではサムネイルを表示せず、タイトルと要約に全幅を使う。ヒーローのイラストで世界観を担保する。
- タグは折り返す。横スクロールを必須にしない。
- クリック対象の高さは 44px 以上を目安に確保する。
- 常設サイドバーや、記事を覆う固定ボタンを置かない。

## 実装時の検証

1. 320 / 390 / 768 / 1440px でレイアウトと長い記事名・タグ名を確認する。
2. 日本語本文は通常文字でコントラスト比 4.5:1 以上を実測する。
3. キーボードで全リンクに到達でき、フォーカスが見えることを確認する。
4. イラストの代替テキストは、装飾なら空にする。著作者・出典は採用する実素材に合わせる。
5. イラストは配信サイズを最適化し、記事画像には寸法を指定して表示のずれを防ぐ。
6. タグ遷移、記事リンク、新着順、RSS は本体実装時に動作確認する。

生成画像の文字・余白・色は参考であり、上記数値や機能の動作を保証するものではない。
