## 自動化したいことを整理する

まずは、普段の作業を振り返り「繰り返している作業」「時間がかかる作業」を書き出しました。すべてを一度に自動化しようとすると続かないので、効果が小さくても、すぐ試せるものから着手します。

| 作業内容                 | 頻度    | 課題                     | 優先度 |
| ------------------------ | ------- | ------------------------ | ------ |
| 日報のひな形作成         | 毎日    | 同じ項目を入力する       | 高     |
| スクリーンショットの整理 | 週に1回 | 手作業で分類する         | 中     |
| ブログの下書き作成       | 週に1回 | 書式を整える時間がかかる | 中     |

> 自動化の目的は、作業をなくすことではなく、考える時間を増やすことだと自分は考えています。

## 小さく試してみる

最初に試したのは、日報のひな形を作るスクリプトです。Node.jsの標準機能だけで、今日の日付を含むMarkdownファイルを作れます。

```typescript
import { mkdir, writeFile } from "node:fs/promises";

const date = new Date().toLocaleDateString("sv-SE");
const content = `# ${date}\n\n## やったこと\n\n## わかったこと\n\n## 次に試すこと\n`;

await mkdir("./notes/daily", { recursive: true });
await writeFile(`./notes/daily/${date}.md`, content, { flag: "wx" });
console.log("日報のひな形を作成しました。既存ファイルは上書きしません。");
```

ファイルがすでにある場合はエラーにして、書いた内容を上書きしないようにしました。小さなスクリプトでも、失敗したときの動作は先に決めておくと安心です。

### 長いコードを読むとき

長い行はコードの枠の中だけを横にスクロールできます。キーボードではコード欄にフォーカスして矢印キーで移動できます。

```typescript
const dailyNoteTemplate = {
    title: "今日の記録",
    sections: ["やったこと", "わかったこと", "明日試したいこと"],
    outputDirectory: "./notes/daily",
    overwriteExistingFile: false,
};
```

## 続けるための工夫

一度作って終わりではなく、使い続けるために工夫しました。

- コマンドを短くして、すぐに実行できるようにする
- READMEに使い方を残しておく
- 定期的に見直して、使わなくなったものは整理する

[Astroの記事](/tags/astro/)も読みながら、このブログの更新手順も少しずつ整えています。

## まとめ

小さな自動化から始めることで、無理なく続けることができました。今後は、スクリーンショットの整理やブログの下書き作成にも取り組み、日々の作業をさらに楽にしていきたいと思います。
