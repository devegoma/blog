## 実装した成果物の受け渡し

`.github/workflows/ci.yml` の必須チェック名 `Checks` は維持しました。Lint・整形・型チェックに続いて `pnpm test` を実行します。このコマンドには単体検査、隔離した記事・生成物の検査、本番ビルドとその成果物検査、検証用ビルド、Chromium・Firefoxの画面テストを含みます。最後に `pnpm test:production-artifacts` を再実行し、全テスト後の本番成果物が正常であることを確認します。

`node scripts/ci-artifact.mjs pack dist release` は、本番成果物を `release/dist/` へコピーします。コピー前後の全ファイルのパス・サイズ・SHA-256が一致することを確認します。シンボリックリンクなど通常ファイルとディレクトリ以外の項目は拒否します。`release/manifest.json` には、コミット、リポジトリ、実行番号、実行の試行番号、全ファイルの照合情報を記録します。manifestは公開ディレクトリの外に置きます。

保存名は `production-<commit>-<run_id>-<run_attempt>`、保存期間は7日です。隠しファイルも保存し、ファイルが存在しない場合は失敗させます。失敗時のPlaywright記録も従来どおり7日保存します。成果物保存後に発行されたIDをChecksの出力として公開ジョブへ渡します。

公開ジョブ名は `Deploy production` です。`needs: checks` と、push・`refs/heads/main`・Checks成功の条件を持ちます。先頭の固定値 `false` によって、現在は必ずスキップします。手動起動やリポジトリ変数、Secretsによる有効化はできません。#69で対策を実装した際には、隔離検証の無効状態の期待値も更新する必要があります。

取得処理は `actions/download-artifact@v8` を使います。他の実行番号やリポジトリを指定せず、Checksが返した成果物IDだけを対象にします。取得後に `node scripts/ci-artifact.mjs verify release` でコミット・実行番号・試行番号・全ファイルを照合し、追加・欠落・変更を拒否します。`release/` の直下も `dist/` と `manifest.json` のみに制限し、公開ディレクトリの外に未検査ファイルが追加されていた場合も拒否します。コミットと成果物の対応はmanifest、Actionsの成果物名、実行サマリー、公開コマンドの `--commit-hash` で追跡します。試行番号も照合するため、再実行する際はChecksを含む全ジョブを再実行してください。

公開コマンドは `release/` 内で実行する `pnpm dlx wrangler@4.135.0 pages deploy dist --project-name blog --branch main --commit-hash "$GITHUB_SHA" --commit-dirty=false --no-bundle` です。Pages blogの本番ブランチmainは、[親Issueの引き継ぎ](https://github.com/devegoma/blog/issues/32#issuecomment-6731893456)で確認されています。記事入力や検証用成果物は公開ディレクトリに含めません。公開ジョブにはビルドコマンドを置きません。

登録済みSecrets `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` は公開ステップの環境変数としてだけ渡します。秘密値の出力・ファイル保存・コマンド引数への埋め込みは行いません。ワークフロー権限は `contents: read` を維持します。
