# Issue #66 検証用・本番用ビルドの分離

状態: 2026-11-10に利用者がQ1〜Q11の推奨案と最終仕様を承認。実装中。

参照: [Issue #66](https://github.com/devegoma/blog/issues/66)、[親Issue #32](https://github.com/devegoma/blog/issues/32)、[用語集](../GLOSSARY.md)。

## 目的と変更範囲

執筆者は、表示確認用サンプルを維持しながら、公開対象だけの成果物を生成する必要があります。従来は同じ記事入力と `dist/` をテストと公開に使っていました。入力・成果物・キャッシュを用途ごとに分け、サンプル依存の検査と本番からの除外検査を両立させます。

公開対象の意味は利用者との質問Q1〜Q11で確定しました。正式記事は執筆・公開の対象、サンプルは表示確認のための検証用記事です。正式記事にも下書きと公開記事があります。サンプルの `draft: false` は検証画面での表示状態であり、本番への掲載を意味しません。

正式記事の執筆、デプロイの接続、ドメイン設定、ブランチ保護は対象外です。検索機能は追加せず、既存成果物に対して除外を検査します。

## 確定した契約

| 要件 | 契約                                                                                                                                           | 拒否する結果                                                             | 検証方法                                                       |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------- |
| R1   | 本番は正式記事だけ、検証はサンプルだけを入力にします。現在の4記事はすべて検証用へ移します。                                                    | 正式記事が検証一覧に混ざる、本番にサンプルが出る。                       | 両用途を交互に生成し、記事集合を検査します。                   |
| R2   | `build`・`preview` は `dist/`、`build:verification`・`preview:verification` は `dist-verification/` を使います。キャッシュも分けます。         | 他用途の成果物を上書きする、キャッシュから記事が混ざる。                 | 出力先と交互生成後の内容を検査します。                         |
| R3   | `dev` は正式記事と下書きの執筆用、`dev:verification` はサンプル確認用です。下書き本文は既存の `SHOW_DRAFTS` 規則を維持し、一覧には載せません。 | 下書きが本番に出る、既存の下書き表示切替が変わる。                       | 下書き・公開状態の既存検査を維持します。                       |
| R4   | 本番は下書き・サンプルの本文、一覧掲載、RSS項目、サイトマップ項目、検索データ、専用画像を含めません。                                          | 非公開記事の内容、リンク、画像が成果物に残る。                           | 混在入力の成果物全体と画像を検査します。                       |
| R5   | 正式記事0件でも必要ページを生成し、ホームに「公開記事はまだありません。」と表示します。                                                        | 空の入力で生成が失敗する、サンプルで補完する。                           | 正式記事0件の生成物を検査します。                              |
| R6   | 正式記事の専用画像は記事の近くで管理します。公開記事が参照する画像だけを本番へ含め、共通画像は公開ディレクトリで管理します。                   | 下書き専用画像が出力される、公開記事の画像が取得できない。               | サムネイル・本文画像と、差し戻し・削除後の成果物を検査します。 |
| R7   | `pnpm test` とCIで両用途を直列に検査します。本番用の追加検査は隔離した入力を使用します。                                                       | 既存のサンプル依存テストが失敗する、入力の一時変更が並行実行で干渉する。 | 全検査を直列実行し、終了後に作業差分を確認します。             |

## worktreeごとのゴールと分担

すべて `c5d2e87` を基点に作成しました。worktreeは元の作業コピーの `tmp/worktrees/` 内にあります。

| worktree              | ブランチ                     | ゴール・所有範囲                                                                                         |
| --------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| `issue66-build`       | `codex/issue-66-build`       | 入力・出力・キャッシュ・コマンドを分離し、サンプルを移動します。ビルド設定とコマンドを担当します。       |
| `issue66-images`      | `codex/issue-66-images`      | 正式記事の画像配置を実装し、下書き専用画像の出力を防ぎます。記事の入力検証と画像の利用箇所を担当します。 |
| `issue66-checks`      | `codex/issue-66-checks`      | 既存検査を検証用成果物へ接続し、本番からの除外を自動検査します。検査スクリプトと画面テストを担当します。 |
| `issue66-integration` | `codex/issue-66-integration` | 共有部分を統合し、説明・執筆手順を更新して全体検証を完了します。                                         |

仕様と検証対象を先に共有し、独立したファイルの実装だけを並列化します。共有するコマンド定義は統合時に調整します。各worktree内のビルド・入力変更検査は直列実行します。

## 変更の安全性と検証環境

既存サンプルの内容と検証時のURL、記事の公開状態・固定URL・タグ・概要の規則を維持します。新たな外部依存は追加しません。元の作業コピーの未追跡 `tmp/` は変更対象にせず、成果物は専用ブランチに保持します。変更の取り消しは各分担コミットを単位に行えます。

ローカル検証はWindows・PowerShell・Node.js 24.22.1・pnpm 12.16.1を使います。Linuxは既存CIの実行対象ですが、この作業中のローカル実行結果と区別して記録します。別worktreeの独立した実行は許容し、同じ作業コピーの入力を書き換える検査とビルド・画面テストは並行実行しません。
