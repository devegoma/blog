# Issue #66 検証用・本番用ビルドの分離

状態: 2026-11-10に利用者がQ1〜Q11の推奨案と最終仕様を承認。同日に実装とWindowsでの統合検証を完了しました。

参照: [Issue #66](https://github.com/devegoma/blog/issues/66)、[親Issue #32](https://github.com/devegoma/blog/issues/32)、[用語集](../GLOSSARY.md)。

## 目的と変更範囲

執筆者は、表示確認用サンプルを維持しながら、公開対象だけの成果物を生成する必要があります。従来は同じ記事入力と `dist/` をテストと公開に使っていました。入力・成果物・キャッシュを用途ごとに分け、サンプル依存の検査と本番からの除外検査を両立させます。

公開対象の意味は利用者との質問Q1〜Q11で確定しました。正式記事は執筆・公開の対象、サンプルは表示確認のための検証用記事です。正式記事にも下書きと公開記事があります。サンプルの `draft: false` は検証画面での表示状態であり、本番への掲載を意味しません。

正式記事の執筆、デプロイの接続、ドメイン設定、ブランチ保護は対象外です。検索機能は追加せず、既存成果物に対して除外を検査します。

## worktreeごとのゴールと分担

すべて `c5d2e87` を基点に作成しました。worktreeは元の作業コピーの `tmp/worktrees/` 内にあります。

| worktree              | ブランチ                     | ゴール・所有範囲                                                                                         |
| --------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| `issue66-build`       | `codex/issue-66-build`       | 入力・出力・キャッシュ・コマンドを分離し、サンプルを移動します。ビルド設定とコマンドを担当します。       |
| `issue66-images`      | `codex/issue-66-images`      | 正式記事の画像配置を実装し、下書き専用画像の出力を防ぎます。記事の入力検証と画像の利用箇所を担当します。 |
| `issue66-checks`      | `codex/issue-66-checks`      | 既存検査を検証用成果物へ接続し、本番からの除外を自動検査します。検査スクリプトと画面テストを担当します。 |
| `issue66-integration` | `codex/issue-66-integration` | 共有部分を統合し、説明・執筆手順を更新して全体検証を完了します。                                         |

仕様と検証対象を先に共有し、独立したファイルの実装だけを並列化します。共有するコマンド定義は統合時に調整します。各worktree内のビルド・入力変更検査は直列実行します。元の作業コピーの検査が別worktreeまで走査しないよう、`tmp/worktrees/` をGit・整形・Lint・型検査の対象から除外します。

## 変更の安全性と検証環境

既存サンプルの内容と検証時のURL、記事の公開状態・固定URL・タグ・概要の規則を維持します。新たな外部依存は追加しません。元の作業コピーにある既存の未追跡ファイルを保持し、今回のworktreeだけを `tmp/worktrees/` に追加します。成果物は専用ブランチに保持し、変更の取り消しは各分担コミットを単位に行えます。

ローカル検証はWindows・PowerShell・Node.js 24.22.1・pnpm 12.16.1を使います。Linuxは既存CIの実行対象ですが、この作業中のローカル実行結果と区別して記録します。別worktreeの独立した実行は許容し、同じ作業コピーの入力を書き換える検査とビルド・画面テストは並行実行しません。

データキャッシュは本番用の `.astro/cache/` と検証用の `.astro-verification/cache/` に分けます。Astroが生成する型情報とコンテンツ参照情報は `.astro/` を共有するため、同じ作業コピーの開発サーバーも同時起動しません。

## 実装と要件の対応

| 要件   | 制約を実施する箇所                                                                                                                                                            | 継続する検査                                                                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1・R2 | `src/config/build-target.mjs` が記事入力・出力・データキャッシュを決め、`astro.config.mjs` が共通素材と検証専用素材を分離します。未設定は本番、不正な指定値はエラーにします。 | `test:build-targets` が記事集合、交互生成、反対用途の成果物のハッシュ不変を検査します。                                                                   |
| R3・R4 | `src/config/post-loader.mjs` が全記事の入力検証後、静的生成時だけ下書きの本文・画像の読み込みを除去します。下書きデータと本文は保持し、次回開発時には再解析します。           | 入力検査、公開状態検査、下書きプレビュー検査、読み込み処理の単体検査を維持します。                                                                        |
| R4・R5 | 公開状態による共通取得処理を維持し、正式記事0件の出力をサンプルで補完しません。                                                                                               | `test:build-targets` が全成果物を走査して本文・タイトル・説明文・記事URL・専用画像名の混入を検査します。既存のホーム・RSS・サイトマップ検査も実行します。 |
| R6     | 正式記事の画像指定をAstro標準の画像情報へ変換し、一覧でも標準の画像部品で描画します。検証用の画像URL文字列は維持します。                                                      | `test:build-targets` が同一内容の表紙・本文画像をHTTPで取得し、下書き専用画像・未参照画像と、差し戻し・削除後の残存を検査します。                         |
| R7     | `package.json` の `test` を直列で接続し、既存CIの同じ入口を維持します。画面テストは検証用プレビューを起動します。                                                             | Lint、整形、型検査、`pnpm test --workers=2` と実行後の差分確認を行います。                                                                                |

実ビルドで、一覧から下書きを除外するだけでは下書きの画像が生成されることを確認しました。全記事の入力検証を先に実行し、公開対象だけの本文・画像を生成へ渡す方式を採用しました。生成後に画像を推測して削除する処理は追加していません。また、同一内容のサムネイルと本文画像で最適化後のURLが一致せず404になる問題を独立検査が検出したため、正式記事の一覧にもAstro標準の画像部品を使用しました。

画像の出典文書は `public/images/README.md` から `docs/design/images.md` へ移しました。出典情報を維持し、本番成果物へ検証用画像名を含む文書をコピーしないための移動です。入力形式の変更はREADMEへ記録しました。
