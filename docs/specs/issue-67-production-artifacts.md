## ゴールと対象範囲

実際に公開する生成済みの本番成果物を読み取り、下書き・サンプルの混入と公開対象との不整合を検出します。検査は記事入力と同じ版の成果物を受け取ります。再ビルドや成果物の修正は行いません。

検査コマンドは `node scripts/check-production-artifacts.mjs [成果物ディレクトリ] [入力ルート]` とします。省略時は実行時の `dist/` とプロジェクトのルートを使用します。成功時は終了コード0、混入・不整合・必須ファイル欠落時は0以外を返し、対象ファイルと理由を表示します。

本Issueでは検査コマンドと検証を実装します。CIの公開処理への接続、実際のデプロイ、検索機能の追加、正式記事の執筆は行いません。後続Issueは、検査に成功した同じ成果物を再ビルドせず公開する必要があります。

## 共通の契約

- 正式記事の入力は `src/content/posts/`、サンプルの入力は `tests/fixtures/content/posts/` です。正式記事のうち `draft: false` の記事だけを公開対象とします。指定省略は下書きです。
- 本文・一覧・RSS・サイトマップ・その他のテキストデータ・記事専用画像の混入を検査します。適用できる既存の成果物整合性検査を再利用します。
- 公開記事や必要な出力の欠落も拒否します。RSSの先頭20件、一覧のページ分割など、既存仕様による掲載範囲を維持します。
- 正式記事0件でも正常な必要ページが存在すれば成功します。
- 一般語や同じタイトルだけを理由に拒否しません。公開記事から利用する画像と `public/` の共通素材を許可します。
- 任意の非公開本文の短い断片を完全に識別する保証は置きません。本文走査の検出条件と変換への対応は、実装した条件に対応する改変テストとともに記録します。
- 期待する記事集合の取得方法と最適化画像の照合方法を実装担当が先に共有し、検証担当が同じ公開インターフェースを使います。

## TDDと検証する境界

利用者が合意したテスト対象の公開インターフェースは、記事入力と生成済み成果物を受け取る検査コマンドです。終了コード・診断・入力と成果物の不変を観測します。内部関数の呼出回数や実装手順はテストしません。デプロイへの接続動作は後続Issueで検証します。

1ケースずつ失敗するテストを先に実行し、最小実装で成功させます。全テストを先に書く進め方は採りません。独立検証で既に検出できる改変を追加する場合は、回帰確認として区別して記録します。

| 検証対象                                                      | 合格条件                                               |
| ------------------------------------------------------------- | ------------------------------------------------------ |
| 公開記事がある正常成果物                                      | 成功します。                                           |
| 正式記事0件                                                   | 必要ページが成立し、成功します。                       |
| 本文・一覧・RSS・サイトマップ・テキストデータ・専用画像の混入 | それぞれを個別に改変し、合意した範囲で拒否します。     |
| 公開対象の欠落・出力間の不整合                                | 拒否します。                                           |
| 共通語句・公開記事でも使う画像・共通素材                      | 誤って拒否しません。                                   |
| 読み取り専用の契約                                            | 検査の成功時・失敗時とも、成果物の内容が変わりません。 |
| 統合後の既存チェック                                          | Lint・整形・型検査・既存テストが成功します。           |

## 実装と検証の記録

### 実装した照合方法

検査はMDXの記事入力を解析し、正式記事の公開状態から期待する記事集合を求めます。記事の並び順と概要生成は既存の関数を再利用します。公開HTMLの集合だけでなく、各一覧の掲載順・記事タイトル・概要、RSSの先頭20件のリンク・GUID・タイトル・概要・公開日を照合します。RSSのチャンネル名・説明文の欠落と、サイトURLの不整合も拒否します。

記事ページの見出し・ページタイトル・説明文も入力と照合します。公開本文はMDXの段落・見出し・コードから得られるテキストのまとまりが本文内に存在することを確認します。式を含む段落は、式の前後を誤って連結した文字列を必須にしないよう対象から外します。MDXを再実行した完全なHTML比較は行いません。

非公開のタイトル・説明文・本文については、空白を正規化した16文字以上のまとまりを対象にします。公開記事の入力にも同じまとまりが存在する場合は、公開可能な内容として許可します。全成果物の生の内容に加え、HTML本文の表示テキストと、JSON・source map・web manifestを解析して得た文字列を走査します。HTMLの装飾や文字参照、JSONのUnicodeエスケープを含む漏出も検証します。

任意の短い断片、任意の変換や分割、MDXの式を実行して初めて決まる内容の漏出は、完全検出の保証対象ではありません。長さはJavaScriptの文字列長で判定します。検索データの生成機能は存在しないため、検索用の特定形式の整合性検査は追加せず、既存テキスト成果物の走査を行います。

記事専用画像は、Astroの画像サービスを最小限拡張して `data-production-source` 属性に元画像の相対パスを記録します。検査は公開記事からの元画像参照と、HTMLの `src`・`srcset` に現れる生成画像を対応付けます。公開記事から参照しない元画像と未参照の生成画像を拒否します。サムネイル・Markdown本文画像は、参照要素と生成画像の両方が消えた場合も拒否します。共通画像は `public/` の同じファイルとの内容一致と出力先の存在も検査します。

この属性は出典の照合に使用します。最適化された画像の内容を再生成して元画像とのバイト同一性を証明する処理ではありません。Astroの内部画像情報 `fsPath` への依存は画像サービス1か所に限定し、実ビルドのテストで対応関係と絶対パス不在を確認します。

### TDDの実施記録

検査CLI未実装の失敗から始め、正式記事0件を最初に成功させました。下書きURLのテキストデータへの混入、公開記事の一斉欠落、RSS欠落、RSS内容の改変、一覧欠落は、拒否できないことをテストで確認してから実装しました。

独立検証では正常な成果物を実ビルドし、1か所ずつ改変・検査・復元します。既存実装が検出するケースは回帰確認として区別し、すべての検査で成果物の全ファイルのハッシュを前後比較します。元の執筆用入力を変更しません。

画像URLのURI表記は正常な実ビルドで検査側だけが失敗することを再現し、Markdown画像URLを復号して解決するよう修正しました。MDX式を含む正常な段落の誤拒否と、RSSのGUIDだけを書き換えても成功してしまう不足も、それぞれ失敗するテストを確認してから修正しました。
