# Issue #27 記事概要の共通生成

状態: 機能仕様とテスト境界に合意し、TDD で実装・検証完了。

対象: [Issue #27](https://github.com/devegoma/blog/issues/27)

## 確定済みの要件

- 任意の説明文を優先する。省略時は本文冒頭の通常の文章から最大120文字を抽出する。
- コード・表は抽出から除外する。抽出できなければ記事タイトルを使う。
- RSS と SNS 共有で同じ生成処理を利用する。
- 日本語、説明文の有無、コード・表のみ、120文字の境界を検証する。
- 用語は既存の [用語集](../GLOSSARY.md) に従う。「説明文」は執筆者の任意入力、「概要」は RSS・SNS で使う紹介文を指す。

## 着手前の調査結果

- `src/data/posts.ts` の `getPosts()` は現在、説明文未指定時にタイトルを `description` へ設定する。
- 元の説明文、MDX 本文、タイトルはそれぞれ `entry.data.description`、`entry.body`、`entry.data.title` から取得できる。
- `description` は記事一覧と記事ページの説明用メタ情報にも利用される。値の変更は既存画面へ影響する。
- `scripts/check-content.mjs` に、説明文省略時のタイトル代用を確認する既存検証がある。
- RSS の生成は #28、SNS 共有情報と共通画像は #30 の担当。両機能は現在未実装。
- 本文のサンプルには段落、見出し、リスト、リンク、画像、コード、表、引用、MDX の補足欄がある。

## ヒアリングで確定した仕様

- 共通概要を記事データに追加し、記事一覧と既存のページ説明も共通概要へ統一する。RSS 本体への接続は #28、SNS 共有情報への接続は #30 で行う。
- 説明文が空文字・空白のみなら未指定として扱う。それ以外は前後の空白を除いて優先する。説明文と代用のタイトルには120文字の制限を適用しない。
- 通常の段落を先頭から順に連結して抽出する。見出し・箇条書き・引用・補足欄・画像・コード・表は除外する。リンクと強調は表示文字だけ残し、インラインコードは除外する。
- 文字数は見た目の1文字単位で数える。改行・連続空白は半角スペース1つへ整える。
- 本文からの抽出結果が120文字を超える場合、先頭120文字を返す。末尾の `...` は付けない。120文字以内ならそのまま返す。

## TDD で検証する公開インターフェース

1. 共通概要の生成関数 `generateSummary({ description, body, title })` の入力と返り値。RSS・SNS 側も利用できる公開関数とし、内部の構文木や解析処理は検証条件にしない。
2. 記事取得の公開インターフェース `getPosts()` と、それを使ったビルド後の HTML。共通概要を取得でき、記事一覧と記事ページの `meta[name=description]` に同じ値が出ること、元の任意の説明文が保持されることを既存の一時記事・ビルド検証で確認する。

既存の `node:test` と `scripts/check-content.mjs` を利用する。テスト対象を合意した後、振る舞いごとに失敗するテスト1件→失敗確認→最小実装→成功確認を繰り返す。モックは使用せず、RSS・SNS の実ルート生成は後続 Issue で接続する。

## 他機能からの利用

`getPosts()` の `post.summary` を RSS の概要と SNS の共有説明に使う。既存の `post.description` は同じ共通概要を保持し、記事一覧と記事ページの説明用メタ情報へ渡す。元の任意入力は `post.entry.data.description` に保持する。

単独で概要が必要な場合は `src/utils/post-summary.mjs` の `generateSummary({ description, body, title })` を呼ぶ。`title` は必須、`description` と `body` は省略できる。MDX の構文木を解析するだけで、本文中のインポートや式は実行しない。

RSS の件数・URL・XML出力は #28、SNS の共有タグと共通画像は #30 で実装する。双方で本文抽出を別途実装しない。
