# 記事の入力検証と既定順の検証（Issue #21）

実施日: 2026-11-01。開始点はリモート `develop` の `c5a636c`（PR #43）。共有作業ツリーとは別のチェックアウトで検証する。

## 変更

- 既存の入力スキーマを `src/data/post-schema.mjs` に移し、`createPostSchema(tags, now)` で時計を渡せるようにする。本番は引数を省略し、記事を検証するたびに現在時刻を取得する。環境変数や記事入力による時計の上書きは追加しない。タグ参照・重複除去の処理はそのまま移動し、#20 のタグ定義検証は実装しない。
- 共通取得の `getPosts()` は `comparePosts()` を使う。公開日降順、同日なら拡張子なしの相対パス全体の文字列昇順。`localeCompare()` は記号を含むパスをロケール依存で照合するため、`a-entry`、`a/entry`、`a0` の順序を直接比較で固定する。更新日は比較しない。
- Node.js 標準の `node:test` を既存の `test:unit` に追加。テスト用の依存は追加しない。

## レビュー指摘対応: 起動中の日付切り替え

スキーマ生成時の既定引数 `now = new Date()` は、開発サーバー起動後も同じ時刻を保持していた。日本時間の午前0時をまたいだ後、その日付の公開日・更新日が未来日として拒否されることを回帰テストで再現した。

固定日時を明示するテスト用引数は維持し、通常は検証処理の中で `now ?? new Date()` を評価する。同じスキーマを再利用しても、公開記事を検証するたびに現在の日本時間の日付で判定する。

Node.js標準の `t.mock.timers` でDateを制御し、同一スキーマを生成したまま日本時間の午前0時を2回またがせる。各境界で公開日・更新日の許否が切り替わること、明示した固定時計は変化しないことを確認する。実際の午前0時まで待つテストや新しい依存は追加しない。

修正前は新しい回帰テストが期待どおり失敗し、修正後は単体9件、test:publication、本番ビルド、Lint、整形、型チェックが成功。

PR #45 のマージ後の develop（`1d4ba86`）を取り込み、#20 のタグ定義検証・参照先付きエラー・test:tags の拡張を維持する形で競合を解消。記事の未定義タグ参照の検証処理は、移動先のスキーマへそのまま引き継ぐ。

競合解消後も単体9件、拡張されたtest:tags、本番ビルド、Lint、整形、型チェックが成功（44ファイル、エラー・警告・ヒント0件）。
