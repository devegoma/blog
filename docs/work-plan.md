## 2026-10-30 00:58 ホーム画面デザイン実装計画

日時は時計ツールの UTC 時刻を Asia/Tokyo（UTC+09:00）へ換算して記録した。

### 目的

確定したホーム画面のデザインを、既存の Astro サイトの `/` に実装する。確認用画像を表示するだけのページではなく、文章・リンク・一覧・切り替えボタンを操作できる HTML と CSS にする。

### 対象範囲

- PC のライト・ダーク配色、太いサンセリフ体のロゴと黄色いアポストロフィ。
- PC の左サイドバー（プロフィール → ナビゲーション → タグ → モード切り替え）と右の記事一覧。
- 記事一覧の一枚の共通背景、記事間の横罫線、16:9 のサムネイル、画像と文章に合わせた行の高さ。
- モバイルの1カラム構成、ロゴ下の右揃えナビゲーション、一覧上のタグ、一覧下のプロフィール、サムネイル非表示。
- ライト・ダークの切り替え動作と、キーボード操作・アクセシブル名・フォーカス表示。
- ホームの見た目を確認できる最小限の表示データ、既存 MDX サンプルへの導線、ホーム変更に伴う既存テストの更新。

### 対象外

- 記事本文・タグ一覧・タグ別一覧・プロフィール・404 の新デザインと実装。
- 本番用の記事管理、公開・下書き判定、タグ管理、10件ごとのページ送り、RSS、サイトマップ、SNS 用メタ情報の実装。要件は維持し、ホームの表示確認用データをこれらの完了とは扱わない。
- 外部 Astro テーマの選定・導入、依存パッケージの更新、Cloudflare 接続、デプロイ、ドメイン設定。
- 本計画作成時点でのソース変更、テスト・Lint・ビルドの実行、コミット、push、PR 操作。

### 前提・制約

- 基準は [デザイン仕様](./design/README.md)、[ライト確定画像](./design/home/desktop-light.png)、[ダーク確定画像](./design/home/desktop-dark.png)。モバイル画像は配置の参考で、旧ロゴ・個別カードをそのまま採用しない。
- `src/pages/index.astro` は環境確認用ページ。`src/layouts/Layout.astro` は MDX サンプルでも使われているため、ホームの変更で本文レイアウトと往復導線を壊さない。
- 既存の Astro・TypeScript・Tailwind CSS・MDX とテスト基盤を使い、まずホームに必要な範囲を直接実装する。既存テーマの導入は保留扱いを維持する。
- `docs/design/home/preview.html` は PC 専用の配置見本で、ヘッダー・サイドバー・写真に画面画像を利用している。実装へそのまま移植せず、画面画像を背景にして文章やボタンを代用しない。
- サムネイル枠は `aspect-ratio: 16 / 9` を基準とし、PC の目安は320×180px、上下余白は20px以上。表示幅に応じて縮小できるようにする。
- 表示確認用のタイトル・日付・要約・画像はサンプルと分かる形で管理する。本番記事や実在するリンク先を勝手に作らない。
- 読了時間は画像上のサンプル表示であり、自動算出仕様は未確定。今回独自の算出処理は追加しない。
- 本文フォントは DM Sans + Noto Sans JP、メタ情報は IBM Plex Mono がデザイン基準。ロゴ書体の確定、素材の利用条件・配布方法は実装前に整理する。

#### 仕様の提案

- 初回は OS の配色設定に従い、手動選択を優先して保存する。保存不可時も切り替えは利用できるようにする。
- モバイルでも切り替えボタンはタグ欄の下に配置する。
- ロゴは既存の単体素材を基準にする。プロフィールと写真は開発用サンプルとして準備し、正式素材と外部リンクの確定は公開準備に残す。
- 既存 MDX サンプルへの記事リンクは動作させる。未実装のタグ・紹介・RSS などは、見た目を残してもリンクやボタンとして操作できる状態にはしない。架空の URL や `#` を設定しない。

#### テスト対象にする公開境界の提案

公開インターフェースはブラウザ上の `/` と、既存の `/posts/sample/` への往復導線。既存 Playwright の6構成を使い、次のユーザーから見える振る舞いを対象とする。

- ホームの見出し・記事一覧・プロフィール・ナビゲーションが表示され、記事リンクから本文へ移動してホームへ戻れる。
- 配色切り替えのマウス・キーボード操作、操作先を示す名前、OS 設定・再読み込み・保存不可時の表示。
- PC の16:9サムネイル、記事間の区切り、モバイルのサムネイル非表示と要素の並び、長いタイトル時を含む横方向のはみ出し防止。

テストでは表示・URL・操作結果・要素の画面上の寸法を観測する。内部関数・private method・特定のコンポーネント分割・保存キー名はテストの契約にしない。色や位置の最終的な見た目は確定画像との目視比較も行う。

合意後は、チェックリストの実装順に合わせて一つの振る舞いについて失敗テストを実行し、最小限の実装で同じテストを成功させる。将来のテストをまとめて先に作成しない。
